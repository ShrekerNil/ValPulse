# ValPulse - 每周指数估值自动化系统

每周自动抓取主要指数估值数据，计算近 10 年 PE/PB 分位，生成可视化周报并推送到微信。全程无人值守：数据抓取、分位计算、图表生成、报告部署、消息推送全部自动完成。

## 功能

- **覆盖范围**：A 股宽基/行业/策略指数 12 个 + 跨境（标普500、恒生科技）
- **分位计算**：近 10 年窗口历史分位，剔除亏损期（PE 为负）样本
- **四级分级**：<20% 低估 / 20-70% 合理 / 70-90% 偏高 / >90% 高估
- **周报内容**：估值总表（含环比）、分位总览条形图、重点指数估值走势图
- **推送**：QQ 邮箱 SMTP 发送 HTML 邮件（估值表格 + 低估/高估名单 + 完整报告链接）
- **失败告警**：流水线整体崩溃时自动发送告警邮件（附 Actions 日志链接），不会静默失败
- **配色**：涨红跌绿（A 股惯例）；估值分位：绿=低估、红=高估

## 部署（GitHub Actions + Pages，全免费）

### 创建仓库并推送代码

```bash
cd D:\Repos\QLProjects\ValPulse
git remote add origin https://github.com/<你的用户名>/<仓库名>.git
git push -u origin main
```

> 仓库公开可享无限 Actions 分钟；私有仓库每月 2000 分钟也远够用（本系统每周约 5 分钟）。

### 配置 QQ 邮箱推送

1. QQ 邮箱 → 设置 → 账户 → 开启 `POP3/SMTP` 服务 → 按提示短信验证后获得 **16 位授权码**（不是登录密码）
2. 仓库页面 → Settings → Secrets and variables → Actions → New repository secret，新建两个 secret：

| Name | Value |
| --- | --- |
| `MAIL_USER` | 发件 QQ 邮箱地址，如 `12345@qq.com` |
| `MAIL_PASS` | 上一步获得的 16 位授权码 |

> `MAIL_TO`（收件地址）可不配，默认发给自己。未配置 `MAIL_USER`/`MAIL_PASS` 时流水线照常运行，仅跳过邮件推送。

### 开启 GitHub Pages

仓库页面 → Settings → Pages → Source 选择 `gh-pages` 分支 → Save

几分钟后访问 `https://<你的用户名>.github.io/<仓库名>/` 即可看到周报。国内访问慢的话本地开代理即可；微信推送摘要本身不受网络影响。

### 定时任务

工作流已配置每周六 08:00（北京时间）自动运行。也可以在 Actions 页面点击 "Run workflow" 手动触发。

## 本地运行


## 运维

### 平时：零操作

不更新代码时，系统按当前版本每周六 08:00 自动运行，你什么都不用做。

远端 main 分支每周会多出一条 `github-actions[bot]` 的「chore: 估值快照」提交，这是正常的快照回推（供下周算环比），不是误操作或他人改动。你的本地仓库会因此逐渐落后于远端，只要不改代码就无影响。

### 更新代码后的操作

改代码和改配置（`config.yaml` 的指数清单、分位阈值等）流程相同：

```bash
# 1. 先拉取远端（远端每周有 bot 快照提交，不拉就推会被拒绝）
git pull --rebase origin main

# 2. 修改代码，提交推送
git add .
git commit -m "描述你的改动"
git push origin main
```

3. **推送不会自动触发流水线**，两种方式看到新版本的效果：
   - 等本周六 08:00 自动运行
   - 立即验证：仓库 → Actions → 左侧「weekly-valuation」→ **Run workflow**（约 4 分钟出结果）

4. 运行成功的标志：收到本周邮件，且 Pages 网页内容已更新。

### 出问题怎么办

- **怎么看状态**：Actions 页面 → weekly-valuation → 运行记录，绿勾为成功，红叉为失败（点进去有完整日志）
- **崩溃告警**：流水线整体失败时会收到一封「ValPulse 运行失败」邮件，附日志直链，点开即可定位报错；只有周报邮件没到但没有告警邮件，说明定时任务未触发，去 Actions 页面确认
- **回滚**：`git revert <出问题的提交>` 后 push，再手动 Run workflow 一次立即生效
- **数据源失效**：若某周多个指数显示「数据不足」（如乐咕改版、IP 被限流），报告照常生成推送，但需要人工介入排查——这是本系统唯一需要你出手的场景

## 调整指数清单

编辑 `config.yaml` 的 `indexes` 列表即可增删指数（code 为乐咕代码格式，如 `000300.SH`）。
添加后首次运行会自动验证数据可用性，抓取失败的指数会在推送中告警。

乐咕已支持的主要指数代码示例：
`000300.SH` 沪深300、`000905.SH` 中证500、`000852.SH` 中证1000、`000016.SH` 上证50、
`399006.SZ` 创业板指、`000688.SH` 科创50、`000932.SH` 中证主要消费、`000933.SH` 中证医药卫生、
`399986.SZ` 中证银行、`000992.SH` 全指金融、`000922.CSI` 中证红利、`000015.SH` 上证红利。

## 常见问题

- **乐咕限流**：该站对频率敏感，已内置 8 秒请求间隔 + 指数退避重试。请勿调小 `interval_seconds`。
- **图表中文乱码**：工作流已安装 Noto CJK 字体；本地运行需系统有中文字体（微软雅黑/思源黑体）。
- **收不到邮件**：先确认授权码正确（16 位，非 QQ 密码）；QQ 邮箱的 SMTP 服务必须处于开启状态；邮件可能进了垃圾箱，加白名单即可。
- **周报链接**：邮件内"查看完整周报"链接指向 Pages 地址，国内访问慢的话本地开代理即可。
- **某周什么都没收到**：见「运维 - 出问题怎么办」：两封邮件都没有说明定时任务未触发，只有告警邮件说明流水线崩溃。
