# ValPulse - 每周指数估值自动化系统

每周自动抓取主要指数估值数据，计算近 10 年 PE/PB 分位，生成可交互的估值看板并推送邮件。全程无人值守：数据抓取、入库、分位计算、看板渲染、部署、消息推送全部自动完成。

## 功能

- **覆盖范围**：A 股宽基/行业/策略指数 15 个（含中证A500、证券公司等）+ 跨境（标普500、恒生科技）+ 黄金
- **数据存储**：SQLite 数据库（`data/valuation.db`）全历史留存，每周由 Actions 自动回推，支持周环比与长期回溯
- **分位计算**：近 10 年窗口历史分位，剔除亏损期（PE 为负）样本
- **四级分级**：<20% 低估 / 20-70% 合理 / 70-90% 偏高 / >90% 高估
- **我的持仓**：按定投视角展示持仓基金对应指数的估值卡片、组合冷热温度与迷你走势，附定投信号建议（低估加大/合理正常/偏高减少/高估止盈）
- **大盘温度**：宽基指数分位等权合成 0-100 温度计，一眼判断整体贵贱
- **交互看板**：单页 HTML，ECharts 绘制估值走势，悬停十字线、时间范围缩放，无静态图、无归档页堆积
- **推送**：QQ 邮箱 SMTP 发送 HTML 邮件（估值表格 + 低估/高估名单 + 持仓信号 + 完整看板链接）
- **失败告警**：流水线整体崩溃时自动发送告警邮件（附 Actions 日志链接），不会静默失败
- **配色**：涨红跌绿（A 股惯例）；估值分位：绿=低估、红=高估

## 数据源（全部免费）

| 数据 | 来源 | 频率 |
| --- | --- | --- |
| A 股指数 PE/PB 历史（约2005年至今） | 乐咕乐股 | 日频 |
| A 股指数 PE 兜底 / A500、证券公司 PE 主源 | 中证指数官网 `index-perf` | 日频 |
| 证券公司、恒生科技 PB 历史 | 蛋卷基金（雪球） | 周频 |
| 标普500 PE 历史 | multpl.com | 月频 |
| 标普500 PB 历史 | multpl.com | 季频 |
| A500、半导体 PB 现值 | 中证指数官方 factsheet PDF | 仅最新一期 |
| 指数行情/涨跌 | 腾讯行情（主）/ 东方财富（兜底） | 实时 |
| 恒生科技 PE 历史 | 乐咕乐股（恒生指数公司数据） | 月频 |
| 黄金历史价格 | 东方财富（主）/ 新浪财经（兜底） | 日频 |

口径说明：
- A 股 PE/PB 优先使用与中证官方整体法一致的加权口径（已交叉验证，差异 <5%）。
- 蛋卷 PB 与中证官方 factsheet 口径存在约 13% 差异（如证券公司 1.1617 vs 1.02），同一指数的 PB 序列不混用两个来源。
- 标普500 PB 为季频，multpl 标注 `†` 的末期数据为估算值。
- 黄金等商品无 PE/PB 概念，看板中仅展示价格历史分位并明确标注。

## 数据处理流程

`python -m src.pipeline` 每周执行一次，流程为：抓取 → SQLite 入库 → 分位计算 → 快照导出 → 看板渲染 → 邮件推送。

### 1. 抓取与来源分发

每个标的由 `config.yaml` 的 `code` / `source` / `pb_source` 决定抓取路径：

| 标的类型 | PE 来源 | PB 来源 |
| --- | --- | --- |
| 普通 A 股指数 | 乐咕 `index-basic-pe`；失败时中证官网兜底 | 乐咕 `index-basic-pb` |
| `source: csi`（A500、证券、半导体） | 中证官网 `index-perf`（`peg` 字段即 PE） | 由 `pb_source` 指定 |
| 标普500 | multpl 月频 PE | multpl 季频 PB |
| 恒生科技 | 乐咕恒生专题页（月频） | 蛋卷周频 PB |
| 黄金 | 无 | 无（仅价格） |

`pb_source` 可选值：
- `danjuan`：蛋卷基金 `pb_history`，周频历史，可算 10 年分位（证券公司、恒生科技）。
- `multpl`：multpl.com 季度 PB 表（标普500）。
- `factsheet`：中证官方 factsheet PDF 中的最新市净率，只有单个快照，无历史（A500、半导体）。

抓取层统一做了：乐咕 8 秒请求间隔 + CSRF 刷新 + 指数退避重试；腾讯行情批量请求；腾讯缺失的标的（跨境指数、中证 H 系列如 `H30184.CSI`）改用东方财富 `2.H30184` 兜底价格；黄金以东方财富 K 线为主、新浪分段数据为备。单个标的异常只记入 `failed` 并在邮件中告警，不阻断整条流水线。

### 2. 入库

- `series` 表：按 `(code, date, metric)` 保存 `pe` / `pb` / `price` 全历史序列，重复运行只更新同一天的值。
- `snapshots` 表：保存每期算好的当前值、分位、分级、样本数，供看板按日期回看。
- 日期统一归一化为 `YYYY-MM-DD`，避免 ECharts 时间轴解析失败。

### 3. 分位计算

- 窗口：近 10 年（`percentile.window_years`）。
- 样本清洗：剔除 `None`、非数值和非正数（亏损期 PE、异常 PB 不参与分位）。
- 分位定义：窗口内小于等于当前值的样本占比（0-100）。
- 分级阈值：`<20%` 低估、`20-70%` 合理、`70-90%` 偏高、`>90%` 高估。
- 样本不足：窗口内样本数小于 `min_samples`（默认 30）时，**PE 与 PB 使用完全相同的处理**——分位仍按实际样本计算，仅把分级置为「数据不足」，避免低样本给出误导性动作建议。
- 频率差异：日频（A 股）、周频（蛋卷 PB）、月频（标普 PE、恒生科技 PE）、季频（标普 PB）共用同一套窗口逻辑，样本数量级不同，解读时需注意。
- 黄金：只计算价格分位，不参与 PE/PB 与温度合成。

### 4. 输出

分位结果写入 `snapshots` 表后导出 `reports/data/series.json` 与 `snapshots.json`，再由 `report.py` 渲染单页看板；邮件摘要由 `push.py` 基于同一份 records 生成。看板与邮件因此始终同源，不会出现口径不一致。

### 5. 已知限制

- 中证A500（2024-09 发布）、恒生科技（2020-07 发布）历史不足 10 年，所谓「10 年分位」实际使用全部可得历史。
- A500、半导体的 PB 只有中证 factsheet 单点现值，分位按单样本计算为 100%，分级固定为「数据不足」。
- 蛋卷 PB 周频且口径与中证官方略有差异，适合看历史位置，不适合与官方 PB 绝对值直接对比。

## 部署（GitHub Actions + Pages，全免费）

### 创建仓库并推送代码

```bash
cd D:\Repos\QLProjects\ValPulse
git remote add origin https://github.com/<你的用户名>/<仓库名>.git
git push -u origin main
```

> 仓库公开可享无限 Actions 分钟；私有仓库每月 2000 分钟也远够用（本系统每周约 20 分钟）。

### 配置 QQ 邮箱推送

1. QQ 邮箱 → 设置 → 账户 → 开启 `POP3/SMTP` 服务 → 按提示短信验证后获得 **16 位授权码**（不是登录密码）
2. 仓库页面 → Settings → Secrets and variables → Actions → New repository secret，新建两个 secret：

| Name | Value |
| --- | --- |
| `MAIL_USER` | 发件 QQ 邮箱地址，如 `12345@qq.com` |
| `MAIL_PASS` | 上一步获得的 16 位授权码 |

> `MAIL_TO`（收件地址）可不配，默认发给自己。未配置 `MAIL_USER`/`MAIL_PASS` 时流水线照常运行，仅跳过邮件推送。

### 开启 GitHub Pages

仓库页面 → Settings → Pages → Source 选择 `gh-pages` 分支 → Save

几分钟后访问 `https://<你的用户名>.github.io/<仓库名>/` 即可看到估值看板。国内访问慢的话本地开代理即可；邮件推送本身不受网络影响。

### 定时任务

工作流已配置每周六 08:00（北京时间）自动运行。也可以在 Actions 页面点击 "Run workflow" 手动触发。

## 本地运行

```bash
pip install -r requirements.txt

```

看板生成在 `reports/index.html`，浏览器直接打开即可交互查看。
本地推送需设置环境变量 `MAIL_USER` 和 `MAIL_PASS`（授权码）。

## 目录结构

```
config.yaml               # 指数清单、持仓配置、分位阈值、抓取参数
src/
  fetchers.py             # 数据抓取（乐咕/中证/腾讯/蛋卷/multpl/factsheet/东财/新浪，限速与重试）
  db.py                   # SQLite 存储（全历史序列 + 每期快照）
  percentile.py           # 近10年分位计算与分级
  signal.py               # 定投信号、组合温度、大盘温度
  report.py               # 单页交互看板（ECharts）
  push.py                 # QQ 邮箱 SMTP 推送
  pipeline.py             # 主流程
data/
  valuation.db            # 估值数据库（随代码入库，每周由 Actions 回推更新）
  snapshots/              # 早期 JSON 快照（仅历史留存，新数据不再写入）
reports/                  # 生成的看板（Pages 托管，Actions 自动部署）
.github/workflows/        # GitHub Actions 定时任务
```

## 配置持仓

编辑 `config.yaml` 的 `holdings` 列表，每只基金对应一个指数代码：

```yaml
holdings:
  - fund: "易方达中证A500ETF联接A"
    code: "000510.CSI"
  - fund: "华宝券商ETF联接A"
    code: "399975.SZ"
  - fund: "易方达黄金ETF联接A"
    code: "GOLD.AU9999"
```

`code` 需与 `indexes` 中的指数代码一致。持仓模块按基金对应指数的估值分位合成组合温度，并给出定投信号建议——仅为数据分析，不构成投资建议。

## 运维

### 平时：零操作

不更新代码时，系统按当前版本每周六 08:00 自动运行，你什么都不用做。

远端 main 分支每周会多出一条 `github-actions[bot]` 的「chore: 估值数据库」提交，这是正常的数据库回推（供下周算环比），不是误操作或他人改动。你的本地仓库会因此逐渐落后于远端，只要不改代码就无影响。

### 更新代码后的操作

改代码和改配置（`config.yaml` 的指数清单、持仓、分位阈值等）流程相同：

```bash
# 1. 先拉取远端（远端每周有 bot 数据库提交，不拉就推会被拒绝）
git pull --rebase origin main

# 2. 修改代码，提交推送
git add .
git commit -m "描述你的改动"
git push origin main
```

3. **推送不会自动触发流水线**，两种方式看到新版本的效果：
   - 等本周六 08:00 自动运行
   - 立即验证：仓库 → Actions → 左侧「weekly-valuation」→ **Run workflow**（约 20 分钟出结果）

4. 运行成功的标志：收到本周邮件，且 Pages 看板内容已更新。

### 出问题怎么办

- **怎么看状态**：Actions 页面 → weekly-valuation → 运行记录，绿勾为成功，红叉为失败（点进去有完整日志）
- **崩溃告警**：流水线整体失败时会收到一封「ValPulse 运行失败」邮件，附日志直链，点开即可定位报错；只有周报邮件没到但没有告警邮件，说明定时任务未触发，去 Actions 页面确认
- **回滚**：`git revert <出问题的提交>` 后 push，再手动 Run workflow 一次立即生效
- **数据源失效**：若某周多个指数显示「数据不足」（如乐咕改版、IP 被限流），看板照常生成推送，但需要人工介入排查——这是本系统唯一需要你出手的场景

## 调整指数清单

编辑 `config.yaml` 的 `indexes` 列表即可增删指数（code 为乐咕代码格式，如 `000300.SH`）。
乐咕未收录的指数加 `source: "csi"` 走中证官网 PE；需要补充 PB 时再按上文指定 `pb_source`（`danjuan` / `multpl` / `factsheet`）。
添加后首次运行会自动验证数据可用性，抓取失败的指数会在推送中告警。历史不足 10 年的指数（如中证A500，2024 年发布）分位实际使用全部可得历史，仅供参考。

乐咕已支持的主要指数代码示例：
`000300.SH` 沪深300、`000905.SH` 中证500、`000852.SH` 中证1000、`000016.SH` 上证50、
`399006.SZ` 创业板指、`000688.SH` 科创50、`000932.SH` 中证主要消费、`000933.SH` 中证医药卫生，
`399986.SZ` 中证银行、`000992.SH` 全指金融、`000922.CSI` 中证红利、`000015.SH` 上证红利，
`000510.CSI` 中证A500、`399975.SZ` 证券公司、`H30184.CSI` 中证全指半导体（腾讯无行情，价格走东财兜底）。

## 常见问题

- **乐咕限流**：该站对频率敏感，已内置 8 秒请求间隔 + 指数退避重试。请勿调小 `interval_seconds`。
- **收不到邮件**：先确认授权码正确（16 位，非 QQ 密码）；QQ 邮箱的 SMTP 服务必须处于开启状态；邮件可能进了垃圾箱，加白名单即可。
- **周报链接**：邮件内"查看完整看板"链接指向 Pages 地址，国内访问慢的话本地开代理即可。
- **某周什么都没收到**：见「运维 - 出问题怎么办」：两封邮件都没有说明定时任务未触发，只有告警邮件说明流水线崩溃。
